# Deploying LibraFlow

Two supported paths:

- **A. Free hosted demo** — Aiven (MySQL) + Render (API, Docker) + Vercel (web). ~20 minutes, $0.
- **B. Any single VM** — `docker compose up -d --build` behind a TLS reverse proxy.

```
Browser ──HTTPS──► Next.js (Vercel)  ──/api/*, /oauth2/*, /login/oauth2/*──►  Spring Boot (Render) ──► MySQL (Aiven)
                   same-origin proxy                                           readiness: /actuator/health/readiness
```

The browser only ever talks to the frontend origin. Next.js forwards API and
OAuth paths to the backend, so the HttpOnly refresh-token cookie is first-party
(`SameSite=Lax`) and the API needs no public CORS surface.

## A. Free hosted demo

### 1. Database — Aiven for MySQL
1. Create a free **MySQL** service at <https://aiven.io>.
2. From *Connection information*, build the JDBC URL:
   `jdbc:mysql://<host>:<port>/defaultdb?sslMode=REQUIRED`
3. Keep the user (`avnadmin`) and password for step 2. Flyway creates the schema on first boot.

### 2. API — Render (Blueprint)
1. Render → **New → Blueprint** → select this repo. It reads [`render.yaml`](../render.yaml).
2. Fill in the prompted values:

   | Key | Value |
   |-----|-------|
   | `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` | from step 1 |
   | `FRONTEND_URL` | your Vercel URL (placeholder now, fix in step 4) |
   | `APP_DEMO_PASSWORD` | password for the seeded demo accounts (≥ 8 chars) |
   | `GOOGLE_*` | leave empty unless you do step 5 |

   `JWT_SECRET` is generated by Render automatically.
3. Deploy. Render only routes traffic once `/actuator/health/readiness` (app **and** DB) is green.
4. Note the API URL, e.g. `https://libraflow-api.onrender.com`.

> Free Render services sleep after ~15 min idle; the first request takes ~1 min to wake.

### 3. Web — Vercel
1. Vercel → **Add New → Project** → this repo, **Root Directory: `frontend`**.
2. Add env var **`BACKEND_API_URL`** = the Render URL (Production *and* Preview).
   It's baked into the proxy at build time, so set it *before* deploying.
3. Deploy and copy the URL.

### 4. Connect them
Set `FRONTEND_URL` on Render to the exact Vercel URL (no trailing slash) and redeploy.
It drives CORS, email links and post-OAuth redirects.

Smoke test:
```bash
F=https://<your-app>.vercel.app
curl -s $F/api/v1/auth/providers        # {"password":true,"google":false}
curl -s -X POST $F/api/v1/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"admin@libraflow.dev","password":"<APP_DEMO_PASSWORD>"}' | head -c 200
```

### 5. (Optional) Google sign-in
1. Google Cloud Console → *APIs & Services → Credentials* → OAuth client ID (Web).
2. **Authorized redirect URI** (note: the *frontend* origin, because of the proxy):
   `https://<your-app>.vercel.app/login/oauth2/code/google`
3. On Render set `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and
   `GOOGLE_REDIRECT_URI` to the same URI. Redeploy.
4. The "Continue with Google" button appears automatically
   (`GET /api/v1/auth/providers` → `google: true`).

## B. Single VM with Docker Compose

```bash
git clone https://github.com/Iampranjaldubey/LibraFlow && cd LibraFlow
cp .env.example .env    # set strong DB_PASSWORD, MYSQL_ROOT_PASSWORD, JWT_SECRET
docker compose up -d --build --wait
```

For a public host, put a TLS proxy (Caddy / nginx / Cloudflare) in front of port
3000 and in `.env` set `FRONTEND_URL=https://your.domain`,
`REFRESH_COOKIE_SECURE=true`, and `APP_DEMO_SEED=false` unless it's a demo.
Port 8080 doesn't need to be public — the frontend reaches the API over the
compose network.

## Production checklist

- [ ] `JWT_SECRET` is random (`openssl rand -base64 48`) and differs per environment
- [ ] `FRONTEND_URL` matches the public origin exactly
- [ ] `REFRESH_COOKIE_SECURE=true` (HTTPS)
- [ ] `APP_DEMO_SEED=false` on any instance with real users
- [ ] `APP_AUTH_REQUIRE_EMAIL_VERIFICATION=true` **and** `MAIL_*` configured, if you want verified emails
- [ ] Health check points at `/actuator/health/readiness`
- [ ] Rate limits (`RATE_LIMIT_AUTH_*`) suit your traffic; the limiter is per-instance (see README → Trade-offs)

## Troubleshooting

| Symptom | Cause / fix |
|---------|-------------|
| Login works, but you're logged out on refresh | `REFRESH_COOKIE_SECURE=true` over plain HTTP, or `FRONTEND_URL` mismatch |
| `502` / `ECONNREFUSED` from `/api/*` on Vercel | `BACKEND_API_URL` missing at build time → redeploy after setting it; or Render is cold-starting |
| Google: `redirect_uri_mismatch` | Redirect URI in Google Console ≠ `GOOGLE_REDIRECT_URI` (must be the frontend origin) |
| `429 Too Many Requests` on login | Rate limiter — wait for `Retry-After` seconds |
| Render deploy never goes live | Readiness failing → check `DB_URL` (`sslMode=REQUIRED`) and DB credentials in logs |
